- 23 个平台保留；22 个具有远程额度查询的平台有独立自动刷新开关，Hermes 本地来源不提供该开关。
- 旧配置默认值、缺失/非法配置、按平台局部更新及持久化；Claude/CommandCode 默认关闭，其他远程平台保持既有自动行为。
- 自动查询在读取凭据、身份和发现账户前按平台过滤；额外账户继承平台设置。手动查询与授权检查仍独立。
- 调度开关不直接清除或重新计时已保存数据；原有缓存有效性及权限清理继续适用。
- Kimi 与 Moonshot 分别控制，钱包自动查询跳过时保留适用历史数值、错误及独立时间；实际新查询已完成的结果不被旧钱包覆盖，撤权仍清除。
- Cursor 自动费用 CSV 服从开关，本地扫描正常继续；只有授权及发布版本一致时才能重放保存的 Cursor 统计。
- 保存失败及快速交错操作不能把失败的开启意图带入另一平台保存；旧自动意图使用最新设置，手动范围和已有密钥/授权队列保持独立。
- 重置恢复兼容默认值但不恢复账户授权；不能因显示开关开启就获得凭据或网络权限。

## 验证方法与边界

Rust 测试使用实际模块/原始函数体配合合成配置、临时文件及测试网络边界；前端测试启动实际模块，使用模拟 IPC、时钟和快照。独立探针另外覆盖保存失败顺序、访问与密钥变化、额外账户、排队、Cursor 历史和 Kimi 钱包竞态。

开关主要控制后续自动查询；已经发出的请求可能完成，不承诺立即撤销网络请求。若设置写入和状态核对都失败，界面会保守暂停自动额度及自动费用扫描，避免状态不明时触发 Cursor 请求；手动刷新仍可用。正常关闭单个平台不暂停本地日志扫描。

本次没有真实账户凭据、用户日志或服务商查询，没有原生 Windows/WebView2 实机验收，也没有 MSVC/NSIS 安装包构建、包体积或性能测量。GNU 目标检查、模拟 DOM 和生产前端构建不能代替这些验收。

编译警告及历史格式差异仍存在；差异检查通过不等于全项目零警告或 Clippy/rustfmt 全通过。两个真实联网探测按原标记忽略，不执行。

使用方式见[每平台自动刷新说明](provider-auto-refresh.md)。此前的 Claude、单账号刷新、CommandCode 验证表仍仅对应各自标注的历史提交。
