# CommandCode GOAT：实验性额度查询

Pane Private 新增 CommandCode，原有 22 个服务商全部保留，合计 23 个。此接入只存在于本私有源码分支，账户权限和自动刷新均默认关闭；**尚未用真实用户密钥验证登录、套餐或额度返回，不能据此认定你的账户已接通**。最初接入的自动化结果见[历史验证记录](commandcode-validation.md)；当前自动刷新设置见[按平台自动刷新](provider-auto-refresh.md)。

## 怎样配置

1. 打开侧栏 **☰ 平台管理（Platform management）**，找到 **CommandCode · 实验性（Experimental）**，打开标题行的**查询（Queries）**。此时还没有授权账户。
2. 在此平台的密码型 **API Key** 输入框中粘贴自己的 CommandCode 密钥并保存。仅在本机应用里填写，**不要发到聊天、截图或问题报告中**。输入框不回显已存密钥；**留空再保存会移除已存密钥**。
3. 单独勾选该账户的查询许可。保存密钥本身只写入本地，不自动勾选账户许可。此版只配置一个 CommandCode 账户，不提供区域选择或额外账户发现。
4. 默认使用 CommandCode 卡片的 **↻ 仅刷新此账号**；也可用侧栏的全局 **Refresh / Ctrl+R** 查询全部已授权账户。自动刷新关闭且尚无查询结果时显示手动查询提示。
5. 如需后台查询，在此平台打开**自动刷新配额**，按现有全局刷新间隔查询已授权账户。此开关不替代第 1、3 步的权限，也不会授权任何账户。

**自动刷新关闭时（默认）**，启动、打开浮窗、定时器、设置和密钥保存所触发的自动刷新都会跳过 CommandCode，不为这些路径读取密钥、身份或查询额度。开启后，获准账户可在这些自动入口查询；显式保存密钥本身仍只进行本地操作，不自动授予权限。手动查询不受自动刷新开关限制，但仍受权限及限流冷却限制。密钥保存期间请等待完成后重新点击刷新；此前排队的手动查询不会沿用到新密钥。关闭自动刷新保留历史结果和原时间，不取消已经发出的请求；关闭账户或平台查询才会撤销访问，隐藏指标只改变显示。

## 数值怎样理解

截至 2026-10-07，[官方使用限额说明](https://commandcode.ai/docs/resources/usage-limits)列出的 GOAT 为每月 **70 credits**、5 小时窗口 **14 credits**、每周窗口 **35 credits**。这是使用额度单位，不应直接标成美元余额；不同模型消耗 credits 的比例可能不同。窗口从首次使用起计时。额外购买的 credits 与套餐窗口额度分开，官方说明其不受这些窗口限制。

卡片按接口实际提供的数据显示：

- **5 小时 / 每周**：使用量、接口返回的窗口上限和有效重置时间；不会用套餐宣传值补出缺失窗口。
- **月度剩余 credits**：只显示余额。本版不从 70 减去余额推算“月度已用”，也不把剩余额度画成已用额度。
- **已购 credits / 免费 credits**：分别显示，不混入套餐窗口已用量。
- **订阅期结束时间**：只有接口提供有效时间才显示，不当成所有窗口共同的重置时间。

缺失、非法或不支持的数值保持未知，不按零处理；缺少重置时间时不补造倒计时，已过期时间也不在本地自动滚动。未知套餐仍可显示有效余额，不自动套用 GOAT 的上限。套餐页的标准数值并不证明某个具体账户具有同样额度。

## 密钥与网络边界

- 密钥仅保存到 Windows 的 `%APPDATA%\PanePrivate\commandcode.json`，使用现有私有文件权限保护，**并非加密存储**。不读取 CommandCode CLI 的 `auth.json`、环境变量或其他工具凭据，不新增 OAuth，也不改写 CLI 登录文件。
- 获准的手动查询或已开启的自动查询只向固定 `https://api.commandcode.ai` 发送 Bearer 认证的两个 GET：`/alpha/billing/credits` 与 `/alpha/billing/subscriptions`。不允许自定义 API 地址、重定向或替代接口探测，不发送模型/推理请求来验证密钥。
- 订阅查询不完整时，有效 credits 数据仍可带警告显示。真实查询失败时保留适用的上次成功数据、原成功时间和错误；保存结果不能当成新的成功。成功替换或移除密钥会清理旧 CommandCode 展示数据。保存报错时按本机提示处理，不应假定磁盘密钥和缓存一定完全未变。
- 没有新增 CommandCode 本地日志来源。已授权快照遵循原有[本地 HTTP API](local-http-api.md)与[隐私边界](privacy.md)，本机能够访问该端口的程序可能读到套餐和用量。

401/403 时在本机核对密钥及其适用账户；429 时等待冷却后再手动刷新。网络、服务或响应格式错误不等于额度为零。无需为排查此接入清除其他平台配置或 CLI 登录。

## 实验性与验证边界

这两个 billing 接口尚无可依赖的公开官方契约。字段解析参考社区项目的 [worker.js](https://github.com/MAXeaglet/commandcode-usage/blob/main/worker.js) 与 [mock_server.py](https://github.com/MAXeaglet/commandcode-usage/blob/main/mock_server.py)，不是稳定性保证；社区 mock 的套餐数值仅用于测试，不能替代官方说明或真实账户响应。

本次未配置真实密钥、读取真实账户凭据或执行真实额度查询。合成接口、DOM 测试及前端构建只能验证对应代码路径；Windows/WebView2 原生交互、真实账户兼容性、MSVC/NSIS 安装包和包体积仍未验收或测量。构建方式沿用[私有版指南](private-build.md)，不需要新的登录流程。
