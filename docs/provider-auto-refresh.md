# 按平台控制自动刷新配额

每个支持账户额度查询的平台都可以单独选择是否自动刷新。此设置只改变自动查询的安排；账户授权、卡片手动查询和独立本地日志权限继续分开管理。

## 在哪里设置

1. 打开侧栏 **☰ 平台管理（Platform management）**，展开所需平台。
2. 在账户设置上方找到**自动刷新配额（Auto-refresh quotas）**。
3. 打开后，当前已授权账户会参与自动额度查询，沿用常规设置中的**全局刷新间隔**。没有新增每平台间隔。同平台明确绑定的额外账户继承此开关，不另设账号级自动刷新开关。
4. 关闭后，平台额度改为手动查询：点击账户卡片的 **↻ 仅刷新此账号**，或用侧栏全局 **Refresh / Ctrl+R** 查询全部已授权账户。手动查询仍遵守账户权限、所选区域/连接模式和限流冷却，不保证绕过 429。

**开启自动刷新不会授权账户。** 平台标题行的**查询（Queries）**与账户勾选仍控制访问。要撤销访问，关闭账户或平台查询；仅隐藏指标不改变任何查询权限。自动刷新偏好可以保存下来，但不替代这些权限。

## 默认值与旧配置

- **Claude、CommandCode：自动刷新默认关闭。** 保留之前默认手动查询的行为；需要时可单独打开。
- **其余支持账户查询的平台：自动刷新默认开启。** 保留之前的刷新方式；新配置的账户权限仍全部关闭，不会因此读取未授权账户。
- **Hermes：没有额度自动刷新开关。** 它是本地统计来源，继续由独立日志来源开关和目录授权控制。
- 旧配置没有此字段或缺少某个平台条目时，使用上述默认值，不改变已有账户授权、区域、密钥或日志来源。

配置中的字段为 `providerAutoRefresh`，以已知平台族 ID 为键、布尔值为值。`claude@…` 等额外账户使用所属平台的条目，不支持按账户 ID 单独覆盖。未知条目和 Hermes 条目不会作为有效额度设置保留；显式非法值按关闭处理，整个字段格式非法时按全部关闭处理。建议使用界面保存，无需为更新手动编辑配置或清空 AppData。

## 关闭后发生什么

启动、打开浮窗、定时器、保存设置及额度重置后的自动补查，都会在**读取该平台凭据、账户身份或发现额外账户之前**跳过其自动额度查询。已授权账户仍可显示适用的历史数据；尚无保留结果时显示手动查询提示。

- 关闭开关本身不删除历史、不伪造新的成功或尝试时间，也不把旧错误改成成功。既有缓存到期、安全清理和相关账户配置变更规则仍适用。
- 保存的数据尚未重新核对当前账户，可能对应此前的 CLI 登录。切换登录后请手动刷新，不把历史数据当作新账户已验证结果。
- 关闭不会取消已经发出的请求，该请求仍可能完成；随后排队或新触发的自动刷新使用最新设置。
- 再次开启后，已授权账户可以参与后续自动刷新；开关不承诺立即查询成功，也不会绕过权限、错误或冷却。
- 关闭自动刷新不等于撤销查询或登录刷新权限。卡片、全局刷新、显式目录识别、经确认的额度重置等操作继续遵守各自权限和范围。

只读[本地 HTTP API](local-http-api.md)仍可返回当前获准的保存结果和手动查询状态；读取 API 不会触发被跳过的远程查询。缓存仍是私密数据，关闭开关不是安全擦除。

## 保存失败时

若出现保存失败提示，不要假定刚才的点击一定已保存或一定已回滚。应用会重新核对已保存的开关；无法核对时会显示自动查询暂停。以重新核对后的状态为准；若无法核对而暂停，修正问题并成功保存后可恢复自动查询。为避免状态不明时触发 Cursor 远程统计，这种“双重失败”的保护状态也会暂时暂停自动本地费用扫描；正常关闭某个平台开关不会暂停本地扫描。手动刷新仍可使用且需要既有账户权限。无需清空账户配置或凭据。

## Kimi Code 与 Kimi API 钱包

Kimi Code 套餐（`kimi`）与 Kimi API / Moonshot 钱包（`moonshot`）有**各自的账户授权和自动刷新开关**，即使钱包显示在 Kimi Code 卡片内也不例外。

- **Kimi 自动开启、Kimi API 自动关闭**：自动更新获准套餐，不读取或查询 Moonshot 钱包；保留适用的已保存钱包数据、原错误及钱包自己的时间，套餐的新时间不会让钱包变成新数据。
- **Kimi 自动关闭、Kimi API 自动开启**：套餐保持历史状态，已单独授权的钱包仍可按自己的设置自动查询。不要把 Kimi 开关当成钱包开关，也不要假定每次都会合并在同一张卡片内。
- **点击 Kimi Code 卡片的 ↻**：始终只查询该 Kimi 套餐，不附带钱包查询，不受这两个自动开关的开关状态限制。
- **点击全局 Refresh / Ctrl+R**：可以手动查询全部已授权账户，包括单独获准的钱包，即使自动刷新关闭。单独显示的 Kimi API 卡片只查询 `moonshot`。
- 撤销 Kimi API 账户权限后，钱包行、来源信息和钱包错误从发布结果中清除。Kimi 套餐授权或自动刷新开启都不能代替钱包权限。

完整的单账号范围与历史钱包标记见[单账号额度刷新](scoped-quota-refresh.md)。

## Cursor 远程用量与本地统计

Cursor 的认证用量 CSV 是远程请求，也遵守 Cursor 的自动刷新开关。关闭时，自动统计流程跳过这项下载，不因本地统计仍在运行而继续读取 Cursor 凭据或发起 CSV 请求；仍然适用的已授权 Cursor 统计可作为保存结果保留。需要更新时使用全局 **Refresh / Ctrl+R**，仍需 Cursor 账户授权。

这个远程例外不改变真正的本地日志扫描：其他已授权日志来源仍按原有目录权限和刷新间隔运行。保存的远程统计不是新的查询成功。

## 不受这个额度开关影响的设置

- 本地日志来源、允许目录和定期本地统计仍按原有规则运行；额度查询关闭不会撤销日志权限。
- 公开模型价格表仍只在手动点击**同步最新价格表**时下载，自动刷新不触发价格同步。
- 区域/连接模式、代理规则、账户授权、指标布局及 Windows 发布打包方式均沿用既有设置。

这是额度自动查询控制，不是整个应用的断网开关。已经发出的请求及显式手动操作仍有各自的行为和权限边界，见[隐私说明](privacy.md)。

本次代码与自动化验证结果见[验证记录](provider-auto-refresh-validation.md)。

退出旧开发进程和托盘应用，使用完整新源码，保留 `%APPDATA%\PanePrivate` 中的用户配置。在 Windows 源码根目录执行 `npm ci` 后，按[构建与使用指南](private-build.md)重新构建或运行。无需删除现有权限、密钥、缓存或日志。
