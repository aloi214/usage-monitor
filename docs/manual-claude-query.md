# Claude 额度：默认手动，可开启自动刷新

**当前用法已更新**：Claude 默认关闭自动刷新，可在平台管理打开**自动刷新配额**。卡片的 ↻ 只查询该账户，全局刷新 / Ctrl+R 查询全部已授权账户；两种手动入口不受自动刷新开关限制。详见[按平台自动刷新](provider-auto-refresh.md)与[单账号额度刷新](scoped-quota-refresh.md)。

本文下方保留的是原手动查询版本的历史验证记录，产品代码为 `53e60b274514868673023d78db83f2b0f75dd8c3`，基于设置更新源码 `e5b40b7`。这些测试数量不覆盖后续单账号刷新、钱包时间修正、release 打包配置、CommandCode 或按平台自动刷新。

## 使用方式

- **只查询一个 Claude 账户**：点击该账户卡片标题行的 **↻ 仅刷新此账号**，包括明确绑定的额外账户。默认账户和同平台其他账户不随之查询。
- **查询全部已授权账户**：点击左侧工具栏的全局刷新按钮，或按 **Ctrl+R**，仍会刷新当前获准的全部账户，包含 Claude。
- **自动刷新配额关闭时（默认）**，启动程序、打开面板、刷新定时器、保存设置和重置额度后的自动补查都会跳过 Claude，不为这些自动查询路径读取其登录凭据、发现额外账户或读取账号身份。
- **需要自动查询时**，在平台管理的 Claude 设置中开启**自动刷新配额**，再确认所需账户已分别授权。同平台额外账户继承此开关，使用全局刷新间隔；它不会自动授权账户。
- 独立的本地日志统计仍遵守自己的来源权限。关闭 Claude 自动额度查询不会关闭获准日志的定期统计。
- 账户授权仍然必要。手动刷新不会自动启用账户、扩大授权范围或跳过限流冷却。
- 正在保存访问权限或确认后的重置尚未完成时，手动查询暂不执行；等保存完成后重新点击。旧的排队点击不会查询后来才启用的账户。
- 显式识别账户目录、兑换重置额度等手动操作仍遵守原来的授权规则；这些操作所必需的认证请求未被关闭。

自动刷新关闭且尚无查询结果时，Claude 卡片显示手动查询提示。已有结果会标明为保存的数据，保留原来的成功时间；跳过自动查询不会伪造新的成功时间。真实查询失败仍保留实际错误，只有失败记录时，本地 HTTP 输出的时间保留原来的实际尝试时间。关闭自动刷新不撤销权限、不删除历史，也不取消已经发出的请求；随后排队或新触发的自动刷新使用最新开关。

保存的结果可能对应此前的 CLI 登录，并不表示后台已重新验证当前账号。切换登录后请手动刷新。关闭授权或相关账户上下文变化仍会使对应缓存失效。

**手动模式不能保证不再遇到 429。** 冷却期间点击刷新仍会遵守已有等待规则。本次没有更改 OAuth 令牌刷新阶段的错误分类或不确定结果保护；额度查询的限流与登录刷新失败仍需分开诊断。

## 更新源码

1. 在旧开发版终端按 Ctrl+C，退出仍在托盘运行的旧程序。
2. 解压完整新源码到源码目录；保留用户配置，不要清空 AppData 或凭据文件。
3. 在源码根目录运行：

```powershell
npm ci
npm run tauri dev
```

Windows 打包方法继续使用[构建指南](private-build.md)。平台管理和日志位置功能见[设置更新说明](settings-update.md)。
