## 上一版实现

- 保留 22 个内置平台，移除 One/New API、Sub2API 自定义中转服务。
- 移除遥测、上游更新检查/下载/安装；使用独立的 Pane Private 应用身份及配置目录。
- 平台/账户查询需明确授权，本地日志目录另行独立授权；关闭和重置会拦截迟到结果。
- 区域、密钥模式和本地连接模式明确选择，请求目的地受限，禁止跨区域、重定向或认证头猜测回退。
- 六类 OAuth 适配器共享刷新协调与安全写回；保留外部客户端并发修改的检测和失败处理。
- 本地缓存保存头尾样本的 SHA-256 指纹，不保存原始片段；旧版、损坏或指纹非法的缓存会失效处理。
- 公开价目表只在点击同步时下载，整批校验后一次提交。重新计价不请求账户或 Cursor，不改变 token 数或 Cursor 已报告费用。
- 缺价模型保持未知；合并为 Others 后仍保留未知状态，未知平均单价不生成误导性图形。
- 新增授权、区域及价格设置支持中英文；俄文使用既有英文回退。

## 可复现命令

准备对应平台工具链和依赖后，在源码根目录运行：

```sh
node --test scripts/*.test.mjs
npm run build
cargo test --locked --manifest-path tests/core-harness/Cargo.toml
cargo test --locked --manifest-path tests/scan-harness/Cargo.toml
cargo test --locked --manifest-path tests/network-harness/Cargo.toml
cargo test --locked --manifest-path tests/refresh-harness/Cargo.toml
```

不要添加 `--ignored`，否则可能运行需要真实数据的探测测试。便携测试包的通过结果不等于 Windows 原生运行结果。

本次 Linux 环境额外运行了以下交叉类型检查；需要另行准备真正的 Windows GNU 交叉编译工具链：

```sh
cargo check --locked --manifest-path src-tauri/Cargo.toml --tests --target x86_64-pc-windows-gnu
```

Windows 本机构建和试运行方法见 [构建与使用](private-build.md)。手动 GitHub Actions 工作流仅作为构建入口保留，本次没有推送仓库或触发它。

- 目录规范化及重复检查不等于操作系统级别的无竞态路径打开。当地其他进程能更改文件系统时仍有 TOCTOU 风险。
- 本地 HTTP API 对本机进程可读，可能暴露授权范围内的显示名称、套餐、使用量等信息；不是凭据接口，但也不是无敏感性的数据。见 [本地 API](local-http-api.md)。
- 本地日志无法证明付费账户归属；StepFun 配置的套餐档位只是偏好，日志也可能包含非套餐调用。估算不是实际账单。
