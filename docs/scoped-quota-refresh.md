# 单账号额度刷新

本文记录产品代码 `b052d41cc63ee7c09e1ab849645df8178eda9473` 引入的刷新方式，[当时的验证记录](scoped-refresh-validation.md)只适用于该提交。后续新增的 [CommandCode](commandcode-provider.md) 与 Claude 都默认手动查询，现在可分别开启[按平台自动刷新](provider-auto-refresh.md)。CommandCode 最初接入的验证另见[历史记录](commandcode-validation.md)。

账户卡片现在提供 **↻ 仅刷新此账号**。适合只想更新某个已授权账户的额度，不必为了它手动查询全部平台。Windows 发布构建同时改为以体积为优先，详见[打包说明](release-package.md)。这些都是私有源码分支的修改，上游安装包不包含它们。

## 怎么用

1. 在**平台管理**中授权要查询的账户。卡片刷新不会自动授权、识别新目录或启用其他账户。
2. 点击该账户卡片标题行的 **↻**。悬停提示及辅助功能名称会标明“仅刷新此账号”和账户名称；请求进行中或排队时，按钮显示忙碌状态并暂时不可重复点击。
3. **侧栏全局刷新 / Ctrl+R 仍然保留**，用于手动刷新全部已授权账户，包括 Claude 和 CommandCode，并按既有流程更新获准的用量统计。公开价格表仍只有在点击“同步最新价格表”时才下载。

“此账号”按卡片绑定的完整账户 ID 区分。例如 `claude` 与 `claude@<hash8>` 是不同目标；点击一个额外 Claude、Codex 或 OpenCode 账户，不会查询默认账户、同平台其他账户或其他平台。纯本地日志来源卡片没有账户额度刷新按钮，Hermes 也不提供远程额度查询。

单账号刷新本身不启动全局日志扫描、价格下载或全部账户刷新，不推进全局“已更新”时间。已有定时刷新、设置变更刷新或此前发起的日志扫描仍可能独立进行；点击卡片不会暂停这些工作，因此不能把它当作整个应用的静默联网模式。Cursor 等账户适配器原本包含的账户用量接口仍可能在该账户查询中执行。

## 查询范围、排队与权限

- 后端在读取账户凭据、身份或发现额外账户之前检查并收窄到精确目标。未知、未授权或已禁用目标直接拒绝，不把账户 ID 当成平台通配符。
- 全局和单账号额度查询串行执行。另一项查询未完成时，点击其他账户会按账户排队；同一忙碌或已排队账户不会重复入队。
- 修改访问权限或开始重置会使旧的排队意图失效。访问设置尚未保存完成时，请等待提示消失后重新点击；旧点击不会取得后来新增的权限。后端也会在执行和发布结果时复核授权。
- 请求失败、服务商拒绝或正在冷却时，保留适用的上次成功数据及错误提示。点击卡片仍受既有登录刷新保护和限流冷却约束，不保证绕过 429。

## 其他卡片和时间怎样保留

单账号查询完成后，后端将目标结果合并到**当前仍有权限的完整账户快照**，并返回整个合并结果。前端采用这份权威结果，不把只有目标账户的小数组覆盖全部卡片，也不擅自恢复后端已撤销的数据。

与本次查询无关且权限未变的卡片保留数据、成功/尝试时间和已有错误。界面仅重绘需要变化的账户卡片，尽量保留滚动位置及焦点；本次卡片刷新不重绘本地日志统计。账户查询、HTTP 输出、托盘与告警仍使用当前权限过滤，撤权及必要的安全清理优先于保留旧显示。

## Kimi 套餐与 Moonshot 钱包

Kimi Code 卡片可以同时显示套餐额度和另行授权的 Kimi API（Moonshot）钱包。这是两个独立账户的数据：

- 点击 **Kimi Code 卡片的 ↻ 只查询 Kimi 套餐**，不会查询 Moonshot 钱包，也不会读取其凭据。
- 如果卡片原有获准钱包数据，会保留钱包数值、原有错误和钱包自己的时间，显示 **已保存的 Moonshot 钱包**。没有可信钱包时间时显示“钱包查询时间未知”；本次套餐查询的时间不能替代钱包时间。未取得过的钱包数值不会被虚构出来。即使尚无任何钱包数值，已保存的查询错误也会显示；已有尝试时间与成功时间分别标注。
- 如需一并更新合并卡片的钱包，请点击**全局刷新 / Ctrl+R**，并确认 Kimi API 账户已经单独授权、地区设置正确。独立显示的 Kimi API 钱包卡片，其刷新目标仍是 `moonshot`。
- 撤销 Kimi API 权限后，合并卡片中的钱包行、钱包来源信息和该钱包的错误提示都会被移除；Kimi 套餐授权不能保留钱包访问。
- 本地 HTTP API 会把保存的钱包行标为历史数据，并提供独立来源和时间；顶层 `stale` 也为 `true`。详情见 [HTTP API](local-http-api.md#saved-wallet-lines)。

## 自动刷新与手动入口互相独立

每个支持账户查询的平台都有**自动刷新配额**开关，同平台额外账户继承它。Claude 和 CommandCode 默认关闭，其余平台默认开启；Hermes 是本地日志来源，没有此开关。关闭时，启动、打开面板、定时器、设置变更和自动额度补查跳过该平台，在读取凭据、身份或发现额外账户之前就停止，并保留获准历史结果。开启不会授予账户权限，仍需分别授权。

卡片刷新只查询该账户；全局刷新 / Ctrl+R 查询全部已授权账户，两者都不受自动刷新开关限制，仍遵守权限和冷却。关闭自动刷新不取消已经发出的查询。保存的数据可能属于此前的 CLI 登录，切换登录后请手动查询。完整规则见[按平台自动刷新](provider-auto-refresh.md)，Claude 的历史说明见[默认手动查询](manual-claude-query.md)。

## 更新与验证边界

退出旧开发进程及托盘应用，使用完整新源码，保留 `%APPDATA%\PanePrivate` 配置。在 Windows 源码根目录执行：

```powershell
npm ci
npm run tauri dev
```

需要安装包时改用 `npm run tauri build`。完整条件和输出位置见[构建指南](private-build.md)及[打包说明](release-package.md)。无需为此次更新清空用户配置、登录凭据或日志。

本说明依据当前源码中的作用域、队列、合并发布和历史钱包标记逻辑。相关自动化检查位于 `scripts/account-refresh.test.mjs`、`scripts/release-package.test.mjs` 和 `tests/usage-harness/`。该版本的具体执行结果见[历史验证记录](scoped-refresh-validation.md)，不用于代表后续 CommandCode 或按平台自动刷新版本。 [原 Claude 版本验证](manual-claude-query.md#historical-validation)仅对应其中标明的旧代码提交。
