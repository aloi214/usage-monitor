# Pane 自维护版安全改造设计

日期：2026-10-07。基线：Pane 0.4.57，提交 a55578c7b10c2ef1d136dc4decaefcaa0fb7a15e。

状态：2026-10-07 用户已同意推进，并明确移除 One/New API、Sub2API 这类自定义中转服务。尚未修改产品代码或构建安装包。

## 1. 已确认的目标

- 保留其他现有平台支持、现有面板和本地消费统计；移除 One/New API、Sub2API 这类自定义中转服务。
- 删除遥测及上游自动更新入口。
- 每家账号独立启用；凭据请求限制目的域名及区域。
- 改善 Pane 与本机 CLI/Desktop 同时使用时的 OAuth 刷新协调。
- 将消费缓存用于检测文件变化的原始头尾片段替换为哈希指纹，保留必要统计与索引。
- 在助手自己的云端工作目录修改，不另开 Codex 任务；不读取用户的真实密钥或项目日志。

## 2. 方案选择

直接删遥测、添加刷新锁虽然改动小，但无法解决刷新前的自动凭据发现、旧配置默认全启用和扫描器里的隐式凭据读取。完全重写客户端成本过高，也难以保留全部平台支持。

选择在现有代码内增加统一的访问策略与刷新协调工具，保留各平台解析及展示逻辑。按模块逐步修改和测试，不把“某个卡片隐藏”当作访问授权。

## 3. 账号与本地扫描的边界

新增由后端保存并验证的启用名单。新配置默认为空；旧配置需要一次明确确认，不能直接把“没有被禁用”迁移为已授权。前端传入过滤参数只能缩小范围，不能扩大访问权限。

平台入口开关控制该平台的凭据发现；账号开关控制已明确选择账号的查询和刷新。开启一个平台不会自动开启发现的其他账号。列表中仍展示所有保留的平台，但关闭时不读取其认证文件、不查询、不刷新、不兑换额度。

本地统计另设来源开关和允许目录。统计来源按实际日志产生工具区分：例如通过 Claude Code 使用 Kimi，扫描来源是 Claude Code，统计归属可以是 Kimi。这样不依赖开启 Claude 账户查询才能读取其已授权日志。

扫描器不得为了归类日志而自动打开认证文件。无法不读凭据就识别的额外账号目录由用户明确选择，未能归属的日志保留为来源统计，不猜账号。目录规范化并限制越界链接；不额外遍历项目源码。关停后终止后续调用并禁止迟到结果重新发布；已发送的请求无法撤回。

## 4. 网络目的地

所有携带凭据的请求禁用自动重定向，校验 HTTPS、确切主机及必要端口，拒绝用户名密码嵌入 URL。已支持的本机服务作为显式配置的回环地址例外，不把它推广到任意明文网络地址。

GLM/Z.ai、MiniMax、Moonshot、Qwen、StepFun 的区域由用户明确选择，取消拿同一凭据跨区域试探。不同凭据类型的请求头由适配器明确匹配，不盲试组合。

移除 One/New API、Sub2API 的平台模块、站点及密钥配置入口、后端命令、刷新和统计路由。旧配置中的对应条目不再加载或执行；不自动删除用户机器上已有的凭据文件。删除这类通用自定义中转服务不等于删除 Ollama 等现有独立平台的本机使用方式。其他保留平台不得通过旧的自定义 origin 参数绕过目的地限制。

公共模型价格表改为手动“同步最新价目表”按钮，不设置自动同步开关。只有用户点击才请求固定公开来源，不附带账号凭据或本地统计；启动、刷新额度、扫描日志均不得触发下载。平时使用内置或已缓存价格，并显示最后同步成功时间。下载结果通过格式和内容校验后再替换本地表；失败时保留旧表及旧成功时间，显示失败原因。成功同步后使费用缓存按新的价格版本重算，避免重复累加，不改变 token 用量。缺价模型标记“暂无价格”，不将缺价当作零费用。

## 5. OAuth 刷新

覆盖磁盘凭据轮换的 Claude、Codex、Kimi、Grok，以及 Cursor 的内存令牌刷新、Antigravity 的 Pane 专有缓存。

统一流程：按规范化凭据来源加异步锁 → 锁内重新读取 → 判断现有令牌是否已更新 → 合并同一凭据的并发刷新 → 验证返回账号身份及令牌完整性 → 写回前重新核对原文件版本 → 安全写入。

写入使用随机且独占创建的同目录临时文件，保留句柄、限定权限，保留原文件未知字段。发现外部客户端已经写入新凭据时，不覆盖它；重新读取并返回明确冲突状态。刷新被拒绝时先检查外部轮换，不反复使用失效 refresh token 请求。

若远端已轮换令牌但本地写入失败，明确显示“刷新成功、保存失败”，停止盲目重试；不得把旧备份恢复为当前凭据。取消和并发操作不能清理其他操作的临时文件。

限制：普通的“比较后替换”不能与不配合的外部客户端构成跨进程原子事务。不能承诺彻底消除 CLI/Desktop 刷新竞争；必须单独验证各客户端，发现冲突时优先停止写回而不是覆盖。

## 6. 遥测、更新与缓存

删除遥测模块、调用、专用依赖和相关前端入口。删除更新检查、下载、安装命令、启动定时器、前端监听、上游端点、公钥及更新产物设置。安装脚本和发布工作流不再下载或发布上游产物；本次不创建远程 fork、不推送、不触发发布。

原始头尾片段改存 SHA-256 摘要及采样长度，升级缓存格式。旧版缓存首次遇到时作废并重建，以重算结果替换旧合计，避免重复累加；统计关闭时不读取原始日志，旧缓存仅作失效处理。普通文件替换不保证磁盘取证级擦除。

摘要仍是本地索引，不对外发送；哈希不是加密，也不把哈希文件当成适合公开共享的数据。此改动只保证不在指定指纹字段中保存原文，不宣称统计缓存完全没有模型名、时间或路径。

## 7. 验证与交付

- 遥测/更新：验证运行代码、配置、依赖及命令注册中不存在可用发送或安装路径。
- 启用策略：覆盖首次启动、旧配置、开关中途关闭、缓存读取、账号发现、手动刷新、额度兑换、保存 key 与恢复默认设置。
- 网络：覆盖跨域重定向、区域选错、被移除服务不可达、保留平台目的地限制、回环例外；价格表仅手动同步、重复点击合并、失败保留旧表、成功后费用重算。
- 刷新：使用假令牌和模拟服务验证并发、外部替换、失败写回、取消、无关 JSON 字段保留；不使用真实账号。
- 缓存：覆盖追加、截断、覆盖重写、旧格式迁移、损坏缓存、序列化不含原始片段、无漏计和重复计数。
- 前端：依赖安装后运行 TypeScript/Vite 构建与现有 Node 测试。
- 原生：Rust 单元测试、格式检查；Windows 上完成原生编译及安装包/托盘冒烟验证后才能称可用版本。

当前环境为 Linux，Node/npm 可用，未发现 Rust 工具链；项目包含 Windows 专有依赖。即使补装 Rust 并通过部分测试，也不等于 Windows 原生构建或客户端共存已验证。

交付按实测结果提供源码改动、差异清单、测试结果和未验证项目。编写分步实施计划后按确认方式执行；Windows 构建需要可用的 Windows 环境，或另行授权的远程构建，不自行选择用户电脑或发布到 GitHub。
